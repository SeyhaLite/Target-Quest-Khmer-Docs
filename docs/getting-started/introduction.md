# Target Quest ជាអ្វី?

## ទិដ្ឋភាពទូទៅ

**Target Quest** គឺជាហ្គេម arcade បែប puzzle 2D ដែលអ្នកលេងបាញ់ព្រួញពីធ្នូ
ដើម្បីកម្ទេចសុត (eggs) ដែលដាក់នៅលើវេទិកាឈើ ឬលើដី។ ហ្គេមប្រើ
**រូបវិទ្យាពិតប្រាកដ**៖ ព្រួញហោះជាគន្លងកោង (parabolic trajectory) ដោយសារ
ទំនាញផែនដី ដូច្នេះអ្នកលេងត្រូវគណនា **មុំ** និង **កម្លាំង** ឱ្យបានត្រឹមត្រូវ។

ចំណុចពិសេសរបស់វាគឺ៖ កម្រិត (levels) មិនចេះចប់។ កម្រិត ១–៤ ត្រូវបានរចនាដោយដៃ
(hand-crafted) ហើយពីកម្រិត ៥ ឡើងទៅ ហ្គេមបង្កើតការរៀបចំថ្មីដោយស្វ័យប្រវត្តិ
តាមរូបមន្តគណិតវិទ្យា (procedural generation)។

## របៀបលេង (ផ្ទៀងផ្ទាត់ពីកូដ `Script/player.gd`)

1. **ចុចកណ្តុរឆ្វេង** ហើយ **ទាញ** — ទិសដៅបាញ់គឺ **ផ្ទុយ** នឹងទិសទាញ
   (ដូច slingshot ឬ Angry Birds)។ កូដ៖ `aim_dir = -drag_vector.normalized()`
   (`player.gd` បន្ទាត់ ៥៩)
2. **កម្លាំងបាញ់** អាស្រ័យលើចម្ងាយទាញ៖ ទាញ ២០០ ភីកសែល = កម្លាំងពេញ ១០០%។
   ល្បឿនព្រួញ = `1200 × power_factor` ភីកសែល/វិនាទី (`player.gd` បន្ទាត់ ២២២–២២៣)
3. ពេលកំពុងទាញ អ្នកនឹងឃើញ **ចំណុចស ៥** បង្ហាញគន្លងដែលព្រួញនឹងហោះ
   (trajectory prediction គូរដោយ `_draw()` ក្នុង `player.gd`)
4. **លែងកណ្តុរ** ដើម្បីបាញ់។ ព្រួញនឹងខ្ទប់ (stick) នៅលើអ្វីដែលវាបុក —
   សុត វេទិកាឈើ ឬដី
5. សុតនីមួយៗត្រូវការ **៣ ព្រួញ** ដើម្បីបែក (មើលចំណាំខាងក្រោម)
6. កម្ទេចសុតអស់ → កម្រិតថ្មីលេចឡើងភ្លាមៗដោយស្វ័យប្រវត្តិ

!!! note "លក្ខខណ្ឌចាញ់/ឈ្នះ"
    ហ្គេម **គ្មាន** ការកំណត់ចំនួនព្រួញ គ្មានពិន្ទុ គ្មាន HUD ឬ UI ទេ —
    អ្នកលេងអាចបាញ់មិនចេះចប់ ហើយគោលដៅគឺកម្ទេចសុតឱ្យអស់ដើម្បីទៅកម្រិតបន្ទាប់។
    នេះផ្ទៀងផ្ទាត់ពី `main.gd` (គ្មានកូដពិន្ទុ ឬ game over)។

## បច្ចេកទេសសង្ខេប

- **Engine:** Godot 4.3, renderer `gl_compatibility` (ដំណើរការលើម៉ាស៊ីនចាស់/OpenGL 3.3 បាន)
- **ភាសា:** GDScript សុទ្ធ (គ្មាន C#)
- **រូបវិទ្យា:** ទំនាញលំនាំដើមរបស់ Godot `physics/2d/default_gravity = 980`
  (គម្រោងមិនកែតម្លៃនេះ — ផ្ទៀងផ្ទាត់ពី `project.godot` ដែលគ្មានផ្នែក `[physics]`)
- **ការគ្រប់គ្រង:** កណ្តុរតែប៉ុណ្ណោះ (គ្មាន keyboard/touch)
- **ទំហំអេក្រង់:** 1280×720, stretch mode `canvas_items` + aspect `expand`

## តើអ្នកណាគួរសិក្សាគម្រោងនេះ?

- **អ្នកចាប់ផ្តើម Godot** ដែលចង់ឃើញគម្រោងពេញលេញតូចមួយ (មិនមែនទ្រឹស្តីទទេ)
- **សិស្ស/និស្សិតខ្មែរ** ដែលចង់រៀន game development ជាភាសាខ្មែរ
- **អ្នកសិក្សារូបវិទ្យាហ្គេម** — គន្លង projectile, Euler integration, raycast collision
- **អ្នកចង់រៀន procedural generation** បែបសាមញ្យដែលយល់បានងាយ

## អ្វីដែលគម្រោងនេះ *មិនមាន* (ស្មោះត្រង់)

- គ្មានការរក្សាទុកវឌ្ឍនភាព (save game)
- គ្មាន automated tests ឬ CI
- មានឯកសារខូច/មិនប្រើមួយចំនួន (`Scenes/monster.tscn` យោងរូបភាពដែលគ្មានក្នុង repo,
  `Script/target.gd` គ្មានអ្វីប្រើ, `Scenes/mai19EC.tmp` ជា temp file) —
